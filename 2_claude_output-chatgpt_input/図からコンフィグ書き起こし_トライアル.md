## 0. このドキュメントの読み方

### 0.1 根拠ラベル

各設定には次のラベルで根拠を付けています。

| ラベル | 意味 |
|---|---|
| 【図】 | 物理・論理合成図_4C から直接読み取れる（ラベル・色・線の接続先・凡例） |
| 【論】 | 同じ drawio ファイルの「論理構成図_4C」から読み取れる（合成図に無い情報の補完） |
| 【書 x-x】 | 書籍の該当節・図。例:【書 5-1/図5-1-6】 |
| 【セ】 | セミナー資料。例:【セ 基本編2 #14】＝基本編2.pptx スライド14 |
| 【一般】 | 一般的なNW技術知識に基づく判断（理由を併記） |
| 【推測】 | 図からは読み取れず、上記を手がかりに補った値・設定。**採用前に要確認** |

コンフィグ中の `<TBD:...>` は値が決められないプレースホルダです。`! 【推測】` のようなコメントでその行の根拠を示しています。

### 0.2 採用した記法（機種/OS）

- 図中の機種は「C社 L3switch 9000-24」「C社 Firewall 3000」「C社 Router 1000」「C社 L2switch 3000-24 / 1000-24 / 1000-48」で、**実在の機種・OSは特定できません**。
- 書籍 4-4節に「このコアスイッチは…米Cisco Systems製品をモデルにしています…型番やインターフェース名などは架空のもの」とあり【書 4-4】、ポート名も `Te`/`Gi`/`Po` という Cisco 流の表記です【図】。書籍自身も図から Cisco IOS 形式でコンフィグを起こす例を載せています【書 5-1/図5-1-6】【セ 基本編2 #14】。
- そこで本書き起こしは **Cisco IOS（Catalyst/ISR 系）風の記法** で統一しました。FW も IOS ルーター風に書いており、ASA 等の専用FW OSの文法ではありません。架空機種なので、コマンドの実在性より「図のどの情報がどの設定行になるか」の対応を示すことを優先しています。

### 0.3 図の読み取り方法（AI側の作業内容）

1. drawio.svg に埋め込まれた mxGraph XML（7ページ）を展開し、「物理・論理合成図_4C」を対象にした。
2. 図形（ポート箱・セグメント横線・IPバッジ・GRT箱）とエッジ（線）の **source/target の接続関係**、線の色・太さ・端点記号をデータとして抽出した。
3. 補助として図を画像化し、目視でも確認した。

画像だけでは「どの線がどのセグメントに刺さっているか」を確実には判別できない箇所が多くありました。drawio の接続データがあったので、接続関係はほぼ機械的に確定できています（→ 8章の所感を参照）。

## 1. 物理・論理合成図とは（資料からの確認）

- **目的**: 物理構成と論理構成の対応関係を明確にし、各物理機器が持つべき機能・設定・論理構造との対応を示して、要件を満たせるか、矛盾がないかを机上で検証する図【書 4-4】。セミナーでは「L1/L3の重ね合わせ」「L2/VLAN回りの設計、機材選定の妥当性検証等」と位置付けています【セ 基本編1 #21】。
- **描き方（4ステップ）**: ①物理構成図の機器を大きな箱にする ②論理の構成要素（ポート、セグメント、ルーティング、仮想マシン）を洗い出す ③箱に書き込む ④配置を整える【書 4-4/図4-4-1】。
- **表現ルール（本書き起こしで依拠したもの）**
  - 箱の中央の「GRT」はグローバルルーティングテーブル（L3機能）を表す【書 4-4/図4-4-3】。
  - ポートは箱で表し、複数ポートにまたがる箱は Port-channel（`Po`）【書 4-4/図4-4-4】。
  - L2セグメント（VLAN）は箱の中の横線で描き、IPブロック・VLAN IDのラベルを付ける。GRT・ポートとセグメントを線で結ぶ【書 4-4/図4-4-5】。
  - GRT 側の論理IF（`interface Vlan`）は、Cisco 機では規則的に決まるので省略している【書 4-4/図4-4-6】。→ **セグメントと GRT の接続 ＝ SVI（`interface VlanN`）** と解釈しました。
  - 接続しないポートは描かない【書 4-4】。
  - 同じパターンは省略してよい（全サーバー・全機器を描く必要はない）【書 4-4】。
- **コンフィグへの応用**: 「物理・論理合成図を参照して実際のコンフィグや具体的な設定内容をイメージできる」とし、tk1-core01 の DMZ(VLAN10) と Po1 の例を示しています。一方で「HSRPの詳細な設定など、構成図に表れていない情報は別途ルールを設ける必要がある」とも書かれています【書 5-1/図5-1-6】。

## 2. 図の凡例と、コンフィグ要素への対応付け

### 2.1 図中凡例【図】（合成図右上）

| 図の要素 | 意味（凡例） | コンフィグ上の対応（本書き起こしの解釈） |
|---|---|---|
| 箱左上の Host / Vendor Model | ホスト名・機種 | `hostname` |
| 灰色の「GRT」箱 | Routing (GRT/VRF) | グローバルルーティングテーブル。`ip routing`、SVI、`ip route` |
| 「vrf / mgmt」箱 | VRF mgmt【図】 | `vrf definition mgmt` と管理ポートの VRF 割り当て |
| 色付き横線＋ラベル `NetworkAddr/Prefix VLAN-Name, VLAN-ID` | L2セグメント | `vlan N` / `name` |
| セグメント上の色付きバッジ `.IP` | そのセグメントでの GRT の IP（第4オクテット） | SVI の `ip address` |
| GRT 間の太い半透明線＋`vip .N` | VRRP Pair / VRRP VIP | `vrrp N ip ...` |
| 複数ポートを囲む箱 `Po` | Link Aggregation | `interface Port-channel` / `channel-group` |
| 線の太さ・端点記号 | 下表 | `description`、速度の確認材料 |

ケーブル・コネクタ凡例【図】:

| 線 | コネクタ | ケーブル |
|---|---|---|
| 細線・端点なし | RJ45 | 1000BASE-T (Cat6a) |
| 細線・白丸 | SFP+/RJ45 (10GBASE-T モジュール) | 1000BASE-T (Cat6a) |
| 細線・黒丸 | SFP/LC | 1000BASE-SX (OM3) |
| 太線・黒丸 | SFP+/LC | 10GBASE-SR (OM3) |

## 4. 東京拠点のコンフィグ

### 4.1 tk1-core01（C社 L3switch 9000-24）

```
! ===== tk1-core01 =====
hostname tk1-core01
!
ip routing
!
vrf definition mgmt                         ! 【推測】Mgmt ポートを GRT から分離するため（下記根拠 C-12）
 address-family ipv4
 exit-address-family
!
spanning-tree mode rapid-pvst               ! 【一般】ラダー構成でL2ループがあるため（C-13）
spanning-tree vlan 2,9-11,100-399 priority 4096   ! 【推測】VRRP マスターと STP ルートを揃える
!
vlan 2
 name EXT
vlan 9
 name MGMT
vlan 10
 name DMZ
vlan 11
 name COMMON
vlan 100-199                                ! APx_PROD（業務アプリごとに1VLAN）
vlan 200-299                                ! APx_DEV
vlan 300-399                                ! OFFICE_Fn（フロアごとに1VLAN）
!
!---------- SVI (GRT と各セグメントの接続) ----------
interface Vlan2
 description EXT 172.17.0.0/27
 ip address 172.17.0.4 255.255.255.224
 vrrp 2 ip 172.17.0.6
 vrrp 2 priority 105                        ! 【推測】書籍例(HSRP priority 105)を流用
 vrrp 2 preempt
!
interface Vlan9
 description MGMT                           ! 図ラベルは 172.17.2.0/24（DMZと重複）→ 論理構成図の値を採用
 ip address 172.17.1.1 255.255.255.0
 vrrp 9 ip 172.17.1.3
 vrrp 9 priority 105
 vrrp 9 preempt
!
interface Vlan10
 description DMZ 172.17.2.0/24
 ip address 172.17.2.1 255.255.255.0
```

## 8. トライアルの所感（AIでどこまでできたか）

**読み取れた（ほぼ確定）こと**
- ホスト名・機種、ポート名、LAG の組み、対向機器・対向ポート、ケーブル種別、VLAN ごとのポート所属（access か trunk か、許可 VLAN）、GRT の IP（第4オクテット）、VRRP の VIP。
- tk1-core01 の Po1 の allowed VLAN は、書籍の書き起こし例（`2,10-11,100-399`）と独立に一致しました。図の表現ルールが「コンフィグにエンコードできる粒度」で設計されていることを確認できました。
- drawio のデータでは線の source/target が明示されているので、接続関係はほぼ機械的に確定できました。画像だけでは線の交差や「ジャンプ」の判別が難しく、PNG/PDF だけから同じ精度を出すのは難しいと思われます。

**補完が必要だったこと**
- 冗長化パラメータ、VLAN の個別ID、サブネット長、管理IP、経路の next-hop IP、FW ポリシーは図に無く、論理構成図・書籍のルール・一般知識での補完が必要でした。書籍が「別途ルールを設ける必要がある」とする部分そのものです。
- 省略された対の機器（core02 など）は、「同パターン省略」という作図ルールを前提にしないと書けません。

**逆に、AIが検出できた図の不整合**
- アドレス重複（MGMT/DMZ）、ホスト名重複、ポート名とケーブル種別の矛盾、未接続の線、2つの図の間でのホスト部ルールの不一致、L2 ループの存在。図→コンフィグを「設計の検証」として使うと、レビュー補助として効果がありそうです。

**次のトライアル（コンフィグ→図）に向けたメモ**
- 図に VLAN ID の具体値・VRID・管理IP を図形のプロパティ（drawio のカスタム属性）として持たせると、図とコンフィグの往復変換が確実になります。
- 今回の結線表（3章）とセグメント表（2章）を中間表現にすると、コンフィグからの逆変換もこの表を経由して設計できそうです。
